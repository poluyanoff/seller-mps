# Табличные листинги (FilterTable)

Пересказ Figma-гайда «FilterTable» — шаблонов типовых страниц-листингов на десктопе. Шаблоны ускоряют сборку и держат продукты консистентными. Простые страницы разработчики собирают по ним без дизайнера.

Паттерн состоит из трёх связанных частей: **FilterBuilder** (фильтрация) → **Table** → **Pagination**. Между частями — **16**. Шаблоны отличаются только уровнем фильтрации, таблица во всех одна.

В коде: `TaigaUI.FilterTable` — шаблон целиком, `TaigaUI.FilterBuilder` и `TaigaUI.Pagination` — части по отдельности (карточка «FilterTable»).

Устройство и поведение самого FilterBuilder (в библиотеке Figma — Basic filter) — по гайду компонента «FilterBuilder», ссылка внизу. FilterBuilder фильтрует и таблицы, и списки карточек.

Много параметров, нужны операторы сравнения (>, <, ≠, IN, BETWEEN) или поиск вместе с фильтрами — в основную строку FilterBuilder ставим `SmartFilter` (`smart`), быстрые фильтры остаются. Правила — карточка «SmartFilter».

> Это десктопный паттерн листингов: служебных и клиентских (ЛК). Мобильные фильтры чипсами — в разделе «Фильтры и сортировка».

## Выбор шаблона
- **Неограниченный набор значений** — поле с любыми данными: имя, название, описание. Ищем по нему **поиском**.
- **Ограниченный набор значений** — поле с фиксированным перечнем: статус, тип, окружение. Фильтруем **селектом**.

Правила не пересекаются: шаблон выбирается однозначно.

| Шаблон | Состав данных | Фильтрация |
|---|---|---|
| **1** | только параметры с неограниченным набором | поиск; опционально toggle, segmented |
| **1.1** | неограниченные + 1 ограниченный | поиск + 1 select; опционально toggle, segmented |
| **1.2** | не более 2 ограниченных | 1–2 select; опционально toggle, segmented |
| **2** | неограниченные + 2–3 ограниченных | поиск + до 3 select; опционально toggle, segmented |
| **3** | неограниченные + больше 3 ограниченных | поиск + больше 3 select; опционально toggle, segmented |

### Шаблон 1 — минимальная фильтрация
- Поиск — опционален.
- Select — опционален, до 2.
- Segmented control — опционален, строго по правилу (ниже).
- Toggle — опционален, один.
- Количество результатов — опционально.
- «Очистить» — опциональна, видна только когда есть что сбрасывать.
- Варианты: только поиск; только селекторы (1 или 2); поиск + селект по одному параметру.

### Шаблон 2 — фильтрация по 2–3 параметрам
- Поиск — **обязателен**.
- Select — **обязательны**, до 3.
- Segmented, toggle (один), количество результатов, «Очистить» — как в шаблоне 1.

### Шаблон 3 — много параметров
- Поиск — обязателен.
- Select — обязательны, **видимых до 4**.
- **FilterBuilderModal** (popover filter) — опционален, **скрытых фильтров до 10**.
- Segmented, toggle (один), количество результатов, «Очистить» — как в шаблоне 1.

## Построение FilterBuilder
| | M (по умолчанию) | S |
|---|---|---|
| Основная строка: поиск, селекты, кнопка фильтров | поля `tui-input` M **44**, между ними **8** | поля S **32** |
| Строка быстрых фильтров | **32**, через **12** от основной | **32**, через **12** |
| Весь блок | 88 | 76 |

- **Основная строка.** Сначала поиск, за ним селекты. Поля делят ширину поровну. Справа — кнопка фильтров (`tui-button` secondary 44 / 32, иконка `filter`), если есть скрытые фильтры. За ней может стоять primary-кнопка действия — в M (44) и в S (32).
- **Строка быстрых фильтров.** Слева направо:
  1. segmented control S (32);
  2. чипсы;
  3. тогглы;
  4. «Результат: N»;
  5. «Очистить».

  Между элементами **12**. Тогглы, результат и «Очистить» разделены вертикальной линией 16 `border-normal`. Справа (End) можно положить свои элементы.

### Пресеты
| Пресет | Основная строка | Когда |
|---|---|---|
| **Search** | только поиск, кнопка фильтров | фильтров много или выносить их в строку не нужно |
| **Select** | только селекты, **до 5** (столько слотов в компоненте) | все параметры с фиксированным набором |
| **Search + Select** | поиск, за ним **до 4** селектов | поиск всегда первый |

### Ширина
- Компонент растягивается на всю ширину контейнера.
- Селект — от **180** до **360**. Поиск занимает остаток строки, не уже **180**.
- Кнопки (фильтров и действия) стоят строго в конце строки: сначала кнопка фильтров, за ней кнопка действия.
- Селекты, которые не помещаются при сужении, уходят в поповер (перед его собственными фильтрами). Появляется кнопка фильтров.

### Основная строка: какие поля
В строку можно поставить любое поле ДС размера M (S — в варианте S):
- **ручной ввод** (уникальные номера, ID) — `Input` с крестиком очистки;
- **выбор из готовых значений** — `FilterSelect`, для нескольких значений `multiple`;
- **выбранные значения тегами** — `InputChip`, только если поле не заполнено заранее;
- **дата, время** — `InputDate`, `InputTime`. Дата и время вместе — иконка календаря;
- **период** — фильтр `type: 'period'` (`FilterTable/README.md`, «Фильтр «Период»»), не два `InputDate`;
- **число или диапазон чисел** — `tui-input-range` (slider, range). В ДС его нет (см. «Пробелы»).

### Кнопка фильтров
- Только иконка `filter` (pragmatic). Другие иконки (ползунки, «сортировка») нельзя.
- Текст на кнопке не пишем, подпись — `title` для скринридера.

### Быстрые фильтры: состав и перенос
Набор и порядок в левой части (Start) фиксированные: сегменты → чипсы → тоггл → результат → «Очистить».
- **Сегменты** — одиночный выбор из взаимоисключающих значений («Все», «Активные», «Неактивные»). До **2** групп, в группе до **5** значений. Всегда первые.
- **Чипсы** — выбор нескольких значений (типы объектов, признаки). До **2** групп, в группе до **5** значений. Стоят после сегментов.
  - Чип — `tui-chip` whiteblock S (32), между чипсами **4**, ширина до **180**. Длинный текст обрезается, полный — в тултипе при наведении.
  - Иконки в чипсах не используем.
- **Тоггл** — одиночное условие («Только мои объекты»). Один на строку. Лучше, когда нет сегментов и чипсов. Стоит после чипсов.
- **Результат** и **«Очистить»** — по правилам ниже.

Перенос: если элементы не помещаются в строку, они переносятся на следующую (между рядами **8**).
- Группа чипсов переносится целиком, не по одному чипу.
- Тоггл, результат и «Очистить» переносятся одним блоком.

**End** — правая часть строки, через **64** от Start. Для того, что не относится к фильтрации:
- сортировка списка карточек;
- небольшое действие («Выгрузить таблицу»);
- пагинация по страницам.

Порядок строгий: пагинация → кнопка → кнопка, между ними вертикальная линия. В коде — `quickEnd`.

### Чипсы: логика
- **Единичное значение.** Чип отвечает за одно значение, а не за набор условий. Выбрано несколько чипсов — в выдаче всё, что подходит хотя бы под один («или»).
- Чип не обязан повторять значение селекта: это может быть отдельный способ отбора (например, статусы, которых нет в селектах).
- Если значение чипа есть в скрытом фильтре, оно автоматически проставляется и там.

**Пресеты** — готовые сочетания значений одного или нескольких селектов для частых случаев.
- Стоят чипсами в **первой** группе.
- Связаны с одним или несколькими селектами. Пресет без селекта допустим, если значение всегда зашито в пресет.
- Нажали пресет — его значения проставляются в селекты и скрытый фильтр.
- Пресет включается сам, только когда все связанные настройки точно совпадают с его значениями.
- Изменили что-то вручную — пресет выключается.

### Сортировка
- В таблице сортировка остаётся в шапке таблицы (`Table`, `sort`). Кнопку сортировки в фильтры не ставим.
- В списке карточек сортировка — в End: `tui-button` flat, иконка справа, по нажатию — меню `Dropdown` («По дате создания», «По алфавиту», разделитель, «По возрастанию», «По убыванию»; выбранное — галочкой).

## Элементы фильтрации
**Общее правило:** фильтруем только по параметрам, которые есть в таблице. И наоборот: в таблице должны быть все параметры, по которым есть фильтр.

**Поиск** — `tui-input-search`.
- Стоит в начале фильтрации. Может искать сразу по нескольким столбцам.
- Подпись начинается с «Поиск по» и называет столбцы через «или»: «Поиск по названию или описанию». Неправильно: «Найти по имени».
- Только для параметров с неограниченным набором или задаваемых пользователем (название, описание, группа).
- Если параметр покрыт поиском, отдельный селект для него не делаем.

**Select** — только для параметров с фиксированным набором (статус, тип).
- Подпись повторяет заголовок столбца: столбец «Роли в тенанте» → селект «Роли в тенанте», а не «Выберите роль».
- Выбранное значение сбрасывается крестиком в поле. Список — `Dropdown` того же размера, что поле, во всю его ширину.

**Segmented control** — только для взаимоисключающего выбора.
- **Обязателен** для «Все» / «Мои тенанты» и «Все» / «Мои группы».
- Для других сущностей («Все» / «Мои события») — опционален.
- Стоит **первым** в строке быстрых фильтров: другой тип контрола логически отделяет его от фильтров.
- Порядок сегментов — от большего к меньшему: «Все» → «Мои…».
- «Все» — без уточнения сущности: не «Все группы». «Мои» — с уточнением: «Мои группы», а не «Мои».

**Toggle** — для одиночного условия.
- Подпись всегда начинается с глагола: «Показать только опубликованные», «Показать только в группе», «Показать только управляемые пользователем». «Включить» не пишем.
- Стоит в конце фильтрации.
- Работает как самостоятельный фильтр (связан только со своим столбцом, например «Кем управляется»).
- Либо выносит самое частое условие из селекта: «Показать только опубликованные» дублирует значение фильтра «Статус публикации».

**Popover filter** (FilterBuilderModal) — опционален, для нагруженной фильтрации. Выносит дополнительные селекты в поповер.
- Поповер **408**, радиус **12**, отступы по бокам **24**. При необходимости шире, до **528** (`popoverWidth`).
- Внутри — любые компоненты по задаче: селекты, поля даты, группа чипсов, тоггл (`moreContent`). Выбор в своём контенте отмечайте точкой — `moreActive`.
- Шапка **64** — `tui-header` body-l, справа «Очистить» (`tui-button` flat XS без иконки), под шапкой линия `border-normal`.
  - «Очистить» в шапке сбрасывает только фильтры поповера. Пока в поповере ничего не выбрано — неактивна.
  - Закрывается поповер нажатием вне его, `Esc` или повторным нажатием на кнопку фильтров.
- Контент — поля M через **12**, отступ сверху 20, снизу 24.

**Количество результатов** — «Результат: N», `ui-s`, `text-secondary`. Опционально.
- Количество известно — показываем точное число. Сколько строк сейчас показано на экране, не важно.
- Данные приходят порциями, общее число неизвестно — на первой странице показываем размер порции, дальше сколько уже получено: «Результат: 50», «Результат: 100», «Результат: 153». Без «+».

**«Очистить»** — опциональна.
- `tui-button` flat XS, иконка `arrow-repeat-2`, текст `text-action`.
- Пока ничего не выбрано — не показываем.
- Сбрасывает все фильтры: поиск, селекты (и в поповере), сегменты, тоггл, чипсы.
- После выбора рядом счетчик: «Очистить (2)». Считаем выбранные селекты (и в поповере), сегменты не на первом значении, тоггл и каждый выбранный чип. Поиск в счетчик не входит.

## Таблица
- Компонент `Table`, размеры ячеек **S** и **M**. S — когда нужна высокая плотность данных.
- Наполнение ячеек определяет продуктовая команда по правилам Table.

## Пагинация
Общие правила — раздел «Пагинация», компонент — карточка `Pagination`.
- Нужна, если в таблице **от 100 строк**.
- Основной паттерн — подгрузка кнопкой «Показать еще» (Show more в английском интерфейсе).
- Кнопка «Показать еще» обязательна.
- Счётчик «Просмотрено 50 из N» — опционален, `ui-s`, `text-secondary`, через 12 от кнопки.
- Размер — S (кнопка 32) по умолчанию, или XS (24).
- На страницу грузим фиксированно **50, 75 или 100** записей.
- Когда загружено всё, кнопка скрывается.
- **Есть выбор строк и массовые действия — постраничная пагинация** (решение 25.10.2026). `FilterTable` с `selectable` в `tableProps` ставит ее сам: пейджер + «1 – 50 на странице» (50 · 75 · 100) + «N элементов». Место — `pagingPosition`: под таблицей; в End фильтров, если фильтр закреплен; или сверху и снизу у длинных списков.

## Загрузка и пустые состояния
- **Загрузка.** Первая загрузка, обновление фильтров и пагинация — по гайду лоадеров и скелетонов. Загрузка в селекторах и при ожидании результатов поиска — по гайду `tui-input` (`loading`).
- **Нет исходных данных.**
  - В контентной области — шаблон состояния по сценарию.
  - Фильтрация и пагинация не показываются.
- **Ничего не нашлось по поиску или фильтрам.** Фильтры остаются, пагинация скрыта. В контентной области `tui-block-status` (card, M):
  - иллюстрация 96 `magnifier`;
  - заголовок 20/24 «Не нашли подходящих результатов»;
  - текст `text-secondary` «Попробуйте изменить запрос поиска или настройки фильтров».
- **Ошибка загрузки (системная).** Пагинация скрыта. Тот же блок:
  - иллюстрация `error-red`;
  - заголовок «Не получилось обработать запрос»;
  - текст «Чтобы перезапустить запрос, напишите в чат» (со ссылкой на чат).

Отступы блока: иллюстрация → 24 → заголовок → 12 → текст, ширина текста до 480, высота блока 440.

## Пробелы
- **Тексты для «Нет исходных данных»** зависят от сценария, в гайде их нет. В коде по умолчанию «Нет данных», передавайте свои.
- **Тень поповера** в гайде не указана. Взята `tui-shadow-popup`.
- **`tui-input-range`** (slider и range) гайд FilterBuilder предлагает для чисел и диапазонов. В ДС этого компонента нет.
- **Пагинация по страницам в End**: размеры — по гайду «Pagination pattern» (раздел «Пагинация»). Состояния пунктов пейджера там тоже не показаны.
- **Кнопки в End** («По дате», «Выгрузить таблицу»): в гайде сказано только «flat, иконка справа». Размер не указан. По виду совпадает с «Очистить» (flat XS) — уточнить.
- **Пресеты:** как пресет выглядит включённым, в гайде не показано.
- **Счетчик «Очистить (N)»:** гайд перечисляет селекторы, сегменты, тогглы и чипсы. Не входит ли поиск и как считать мультиселект — в гайде не сказано. В коде: поиск не считается, мультиселект — 1, каждый чип — 1. Число можно задать явно — `clearCount`.
- **«Очистить» в шапке поповера без выбора:** в тексте гайда неактивна, на картинке скрыта. В коде — неактивна.

## Решения по гайду FilterBuilder (24.10.2026)
Где гайд расходится с общими правилами ДС, оставили ДС:
- **Подпись S-селекта** — внутри поля, как плейсхолдер. В гайде подпись над полем, блок 97. Блок S остаётся 76.
- **Длинный текст в чипе** — фейд, как во всех чипах ДС. В гайде многоточие.
