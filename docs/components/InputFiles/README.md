# InputFiles (`tui-input-files`)

Загрузка файлов: фото и сканы документов, дозапросы. Собран по макетам «Origination. Demo Guides (Web) → Паспортные данные → Фото или сканы паспорта». Отдельного гайда по компоненту в материалах нет — значения сняты с макетов.

## Построение
- **Поле 56**, радиус 12, обводка 1 `background-accent-2`, поля 16, подпись Body M 15 по центру.
  - десктоп — обводка пунктиром, подпись «**Выберите файлы** или перетяните их сюда», первая часть `text-action`, остальное `text-primary`;
  - мобилка — сплошная обводка, подпись «Выберите файлы» `text-action`.
- **Под полем через 4:**
  - пока файлов нет — описание Body S 13 `text-secondary`: формат и размер («Файлы pdf, jpg, jpeg, png не больше 30 МБ»). Собирается само из `accept` и `maxSize`. Какие форматы и какой размер — решает продукт под сценарий, общего правила нет; главное — их указать;
  - когда файлы есть — список в рамке `border-normal`, радиус 12, между файлами разделитель 1.

## Файл в списке
| Состояние | Превью | Поля | Текст |
|---|---|---|---|
| загружен | 64, радиус 8: картинка или иконка `medium/doc-blank` 24 `text-tertiary` на `neutral-1` | 10, до текста 12 | имя Body M 15 |
| загружается | 48 с `Loader` 24 | 8 | имя |
| ошибка, десктоп | без превью, иконка `fixed-color/alert-negative` 24 | 8 | имя + причина Body S `text-negative` |
| ошибка, мобилка | 64 с иконкой ошибки | 10 | имя + причина |

- Длинное имя уходит в фейд.
- Справа — крестик удаления 16 `text-tertiary` (`removable={false}` — без него).

## Валидация
Проверка формата и размера — сразу при выборе: неподходящий файл попадает в список с ошибкой «Проверьте формат и размер — подходят файлы pdf, jpg, jpeg, png не больше 30 МБ».

Остальная валидация — по кнопке «Отправить» сценария, тостом (`showToast`):
- ничего не загрузили — «Загрузите файлы»;
- файл ещё грузится — «Дождитесь загрузки файла»;
- есть неподходящие файлы — «Эти файлы не подходят. Проверьте формат и размер».

## Поведение
- Перетаскивание — только десктоп. Пока файл над полем, фон поля `background-neutral-1`.
- Неконтролируемый режим: компонент сам хранит файлы, у картинок строит превью. Контролируемый: `files` + `onChange`, статус загрузки (`status: 'loading' | 'normal' | 'error'`) задаёт продукт.
- Скелетон — плашка 56 с радиусом 12.

## API
```js
h(TaigaUI.InputFiles, { accept: 'pdf jpg jpeg png', maxSize: 30, onChange: setFiles })
h(TaigaUI.InputFiles, { platform: 'mobile', files: [{ id: 1, name: 'Разворот.jpg', status: 'loading' }], onChange: setFiles })
```
Пропсы: `accept` (строка или массив расширений), `maxSize` (МБ), `multiple` (по умолчанию `true`), `files` / `onChange(files)`, `onAdd(added)`, `onRemove(file)`, `removable`, `label`, `description`, `errorText`, `listLabel`, `platform`, `disabled`, `skeleton`, `id`, `className`, `style`.
Файл: `{ id, name, size, src | preview, status, error, file }`.

## Пробелы
- **Отдельного гайда нет.** Размеры и состояния сняты с макетов паттерна «Паспортные данные».
- **Удаление файла** в макетах не показано. Крестик справа добавлен, чтобы прототипы были рабочими. Он вне ДС.
- **Перетаскивание над полем**, наведение, фокус и disabled в макетах не показаны: фон `neutral-1`, `text-action-hover`, рамка фокуса 2 `border-focus`, прозрачность 50 %.
- **Мобильные шрифты.** В макетах мобилки те же 15/24 и 13/20, что на десктопе; в коде — iOS Body M и Body S.
- **Прогресс загрузки** в процентах не описан — только лоадер.
