# Table (`tui-table`)

Таблица организует и показывает данные: по ней удобно перемещаться, сравнивать строки и столбцы, сортировать и фильтровать. Источник — Figma-гайд «Table» (`tui-table-сell`). Компонент десктопный.

## Когда использовать
- **Таблица** — много однотипных записей, нужно сравнивать, сортировать и фильтровать.
- **Data grid** (специальная таблица для работы с данными) — если главное в работе редактирование ячеек и взаимодействие с ними.
- **Список карточек** — если записи сильно различаются, контента много или у элементов уникальная графика.

## Рекомендации
- Значения в столбце соответствуют заголовку; не группируйте в ячейке данные, которые заголовок не описывает.
- Столбец с действиями всегда виден и не уходит в скролл.
- Нагруженную таблицу не кладём в маленький контейнер, где всё придётся обрезать.
- Высота строк одинаковая — так держится вертикальный ритм.

## Ячейки
**Размеры.** В гайде два размера: S плотнее, M свободнее. В Figma у компонента есть ещё L и XL.

| | заголовок | строка в одну линию | отступы | бейдж |
|---|---|---|---|---|
| S | 28 | 32 | 6 / 8 (с подписью 4 / 8) | всегда S |
| M | 44 | 44 | 12 / 12 | M |

- Основной текст — `Body S` 13/20 `text-primary`.
- Подпись над текстом (caption) и второстепенный текст под ним — `Body XS` 11/16 `text-secondary`.
- Заголовок столбца — `Body S Bold` `text-secondary`.

**Типы ячеек:** Header, Text (с caption и second text), Checkbox, Avatar (32), Status (точка 8 + текст), Tag, Badge, Progress bar, Action, Button, Link, Accordion, Text & label.

**Статус: точка или `Badge`** (решение команды, 30.10.2026) — допустимы оба варианта: точка с текстом (`type: 'status'`) или `Badge` `*-pale` в ячейке. В одной таблице — один вариант для всех строк.

**Выравнивание по горизонтали:**
- текст — по левому краю;
- числа, суммы, проценты — по правому, так легче сравнивать разряды;
- исключения, хотя это цифры: даты, телефоны, индексы — по левому;
- заголовок выравнивается так же, как содержимое столбца.

**Действия** — в последнем столбце, без заголовка:
- **Одно действие** — просто в последней колонке.
- **До трёх** — иконками в ряд.
- **Больше трёх** — в меню-кебаб.
- **Удаление** кладём в самое «неудобное» место: если оно среди действий, все действия уходят в контекстное меню.
- **Частое действие** выносим из меню. Если для него нет понятной иконки, ставим кнопку `secondary` с текстом, а не `flat`.

**Лейблы** (бейджи, теги):
- то, что не влезло, прячем в ссылку «+N» с дропдауном;
- если пользователь расширит колонку, лейблы возвращаются в ячейку.

**Ссылки:**
- переход на другую страницу — `tui-link`, mode default;
- псевдоссылки — `show-underline=off`, mode `on light`.

## Построение
- **Строки.** Таблица — строка заголовка и строки с контентом; у каждой строки дивайдер снизу (`border-normal`). Заголовок можно убрать вместе с его дивайдером. Дивайдер у последней строки необязателен.
- **Фон.** На странице таблица лежит на `base` или `base-alt` (`background`). В карточке или модуле наследует фон контейнера (`inherit`).
- **Ширина колонок:**
  - фиксированная — колонка не растягивается и не сжимается; если все колонки фиксированные и строка короче контейнера, разницу получает последняя колонка (или предпоследняя, если последняя — действия);
  - заполнение — колонка тянется на свободное место, можно задать min и max. Без min колонка может сжаться до 0.
  - Подходы можно смешивать.
- **Высота строки:**
  - лучше показывать контент целиком, если высота строк остаётся одинаковой (самая высокая ячейка задаёт высоту, остальные по центру);
  - усечение до одной строки — когда к скрытому тексту обращаются редко;
  - усечение до трёх строк — когда нужно больше контекста.
- **Вертикальное выравнивание:** по центру для обычных строк и для двух строк текста; по верху, если в ячейке 3 строки и больше.

## Поведение
- **Ховер строки** помогает сканировать таблицу, даже если строка неинтерактивная. Фон `neutral-1-hover`, радиус 12; дивайдеры у этой строки и строки над ней скрываются.
- **Справочная таблица без ховера** (`hover={false}`): короткая некликабельная таблица на 2–3 колонки (тарифы, сроки, условия), где сбиться со строки негде, а ховер намекает на клик, которого нет. Строки не подсвечиваются, разделители видны всегда. У таблиц с `onRowClick` и у длинных листингов ховер остаётся.
  - Вместе с ней обычно `flush`: у первой и последней колонки нет бокового отступа, текст встаёт на линию заголовка и описания блока (например, в попапе).
- **Переход по клику** вешаем на всю строку, если внутри нет своих интерактивных элементов, или на отдельные ячейки. Если интерактивны только действия справа, клик можно повесить на несколько ячеек — так область клика больше.
- **Закрепление:**
  - можно закрепить один или несколько столбцов, в том числе первый и последний; середина скроллится по горизонтали, тень появляется только после начала скролла;
  - заголовок тоже можно закрепить.
- **Поиск** подсвечивает совпадения цветом и скрывает строки без совпадений.
- **Сортировка одноуровневая.** Первый клик — по возрастанию, второй — по убыванию, третий выключает. Сортировка по другому столбцу сбрасывает предыдущую. Вся ячейка заголовка с сортировкой реагирует на ховер.
- **Сортировка многоуровневая.**
  - Shift + клик добавляет столбец следующим ключом или убирает его; обычный клик делает столбец единственной сортировкой.
  - Приоритеты пересчитываются сразу: убрали второй — третий становится вторым.
  - Правый клик по заголовку: «Добавить к сортировке», «Сделать первой», «Убрать из сортировки».
- **Настройка колонок:**
  - кнопка крайней справа в шапке, занимает последний пустой столбец; её можно отключить, если колонками управляют снаружи;
  - дропдаун со списком колонок всегда помещается в экран, при длинном списке скроллится;
  - колонки перетаскиваются по всей площади пункта, кроме чекбокса.
- **Массовые действия.**
  - Чекбоксы в строках: выбран или не выбран. В заголовке три состояния: все, ни одной, часть.
  - Сколько выбрано, пользователь видит в панели действий внизу экрана («Выбрано 2», «Выбрать все», действия).

## API в коде
```js
h(TaigaUI.Table, {
  size: 's',                          // s | m
  rows: payments,                     // у строки желательно id
  columns: [
    { key: 'date', title: 'Дата', sortable: true, width: 110 },
    { key: 'name', title: 'Назначение', lines: 1, descriptionKey: 'tag', minWidth: 200 },
    { key: 'who', title: 'Создал', type: 'avatar' },
    { key: 'state', title: 'Статус', type: 'status', statusKey: 'status' },   // positive | warning | negative | info | neutral
    { key: 'sum', title: 'Сумма', align: 'right', sortable: true, render: r => fmt(r.sum) }
  ],
  selectable: true, bulkActions: [{ label: 'Подписать' }, { label: 'Удалить', destructive: true }],
  actions: r => [{ icon: 'small-pragmatic/arrow-in-down', title: 'Скачать' }],
  columnSettings: true, highlight: query, onRowClick: open
})
```
Пропсы таблицы:
- данные и вид: `rows`, `columns`, `size`, `background` (base · base-alt · inherit), `header` (false — без шапки), `lastDivider`, `hover` (false — без ховера строк), `flush` (без бокового отступа у крайних колонок), `verticalAlign`, `label`;
- прокрутка: `stickyHeader`, `maxHeight`;
- сортировка: `sort` / `defaultSort` / `onSortChange` (массив `{key, dir}`), `multiSort`;
- выбор: `selectable`, `selected` / `onSelectionChange`, `bulkActions`;
- действия и колонки: `actions`, `columnSettings`, `hiddenColumns` / `defaultHidden` / `onHiddenChange`;
- поиск и клик: `highlight`, `filterByHighlight`, `onRowClick`, `emptyText`.

Колонка: `key`, `title`, `type` (text · status · badge · avatar · link), `render`, `align`, `width` (число — фиксированная) или `minWidth` / `maxWidth`, `lines` (1 или 3), `captionKey`, `descriptionKey`, `sortable`, `sortValue`, `sticky` (left · right), `hideable`.

Действия строки: `{label, icon, title, onClick, primary, destructive}`. До трёх иконками, больше или с удалением — в меню; `primary` — отдельной кнопкой.

Не сделано в коде:
- правый клик по заголовку для многоуровневой сортировки (работает Shift + клик);
- перетаскивание колонок в настройке;
- «+N» для лейблов;
- ресайз колонок мышью;
- типы Accordion и Progress bar (можно собрать через `render`).

## Листинг с фильтрами
Страницу-листинг (поиск, селекты, «Результат», «Показать еще») собирайте шаблоном `FilterTable` по разделу «Табличные листинги»: в таблице должны быть все параметры, по которым есть фильтр.
