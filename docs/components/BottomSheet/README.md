# BottomSheet (`tui-bottomsheet`)

Шторка по гайду tui-bottomsheet v1.5.0 (15.10.2026): показывается поверх экрана и сохраняет его контекст. Компонент — для **Web / PWA / WebView**. Legacy-часть гайда (старая кастомная шторка) не переносили.

| Платформа | Что это |
|---|---|
| Нативный iOS | обёртка над системной шторкой (зазоры по бокам, скейл контента 0.9 / 0.96, системный спринг) — в вебе не воспроизводим |
| Нативный Android | TUI-компонент на Material, приближен к iOS |
| **Web / PWA / WebView** | TUI-компонент, приближен к iOS — **этот компонент** |

**Когда использовать** — по разделу «Навигация»: настройки экрана (фильтры, сортировка), пояснения и условия, простой выбор, развилка сценария, подтверждения (только PWA). Не для полноценных сценариев и форм из нескольких полей. Шторку в шторку не вкладываем. В модальном WebView шторки не используем.

## Анатомия
`bottomsheet-bar` (индикатор) → `tui-header` → content → footer. Всё, кроме контейнера, необязательно.

## Геометрия (Android / PWA / WebView)
- **Контейнер:** радиус **36** сверху, фон `background-elevation-1`, ширина до **640** (по центру на планшетах и в горизонтальной ориентации).
- **Индикатор:** зона **16** сверху, полоска **32×4** через 8 от верха, радиус 100, `background-neutral-4`.
- **Снизу:** `safe-area + 20` (`env(safe-area-inset-bottom)`).
- **Шапка:** `Header` M, отступы 12 / 16 (высота 48). Шапка всегда закреплена.
- **Контент:** боковые отступы **16** закладываем внутрь компонентов (ячейки, поля), чтобы пресс-стейты шли от края до края. Для произвольного контента — `inset`. С `inset` отдельно стоящие `Cell`, `Header` с `inset` и `Row` компенсируют его сами, поэтому ячейки и произвольный контент можно смешивать без двойных полей.
- **Затемнение:** `tui-service-backdrop`.
- **Аппбар** вместо шапки (`appBar`): `NavigationBar` без статус-бара, с отступом сверху 16 (по гайду tui-appbar), индикатор поверх: iOS 70, Android 72. На Android — отступ 8 от края.
- **Свой верхний отступ** (`topInset`) — если первый элемент нестандартный, например лента чипов (24).
- **Картинка в шапке** (`barOverlay`) — без верхнего отступа, индикатор поверх без фона.
- **Шапка с картинкой, шаблон Xsell** (`hero`): блок картинки своей высоты (по умолчанию 300) и фона, индикатора нет. «Закрыть» — стеклянная кнопка аппбара справа, 16 сверху. Закрытие — крестиком, свайпом и по затемнению.
- **Футер:** кнопки L столбиком через 8, основная сверху, отступ 16 от контента.

## Высота
- `height`: `'auto'` (по контенту, по умолчанию), `'large'` (на всю высоту под статус-баром), число в px или процент.
- **Точки привязки** `snapPoints`, например `[300, 'large']`: маленькая с краткой информацией → средняя → полноэкранная.
- Потянули меньше порога — шторка возвращается к своей точке. Дальше порога — переходит к следующей точке или закрывается. Порог — **50 %** расстояния до следующей точки (для React в гайде — 50 % высоты шторки).
- `display-mode: browser`: шторка на всю высоту получает дополнительный отступ **16** сверху, чтобы не упираться в панель браузера.

## Закрытие
- тап по затемнению (`dismissible={false}` — отключить);
- короткий свайп вниз — если точек привязки нет;
- длинный (быстрый) свайп — закрывает сразу, минуя все точки;
- Esc; на Android — системная «Назад» (в вебе обрабатывает приложение через history).

`onClose(reason)`: `'overlay' | 'swipe' | 'esc' | 'button'`.

- **Блокировка свайпа** (`swipeable={false}`) — обязательно аппбар с «Закрыть». Компонент добавляет его сам, если `appBar` не передан.
- **Алерт при закрытии** — если внутри поля ввода: `onBeforeClose(reason)` возвращает `false` и показывает подтверждение («Действительно хотите закрыть? Введённые данные не сохранятся» — «Закрыть» / «Отмена»).

## Анимация (Android / Web)
| | Кривая | Длительность |
|---|---|---|
| Появление | `cubic-bezier(0.1, 0.8, 0.5, 1)` | 350ms |
| Закрытие | `expressive-exit` | 300ms |
| Изменение высоты | `expressive-standard` | 500ms |

Параметры не зависят от высоты шторки. В вебе затемнение меняется вместе с раскрытием шторки, при перетаскивании — пропорционально.

## Особенности PWA
- **Статус-бар** должен быть цвета затемнённого фона. На iOS 26 красим фон экрана, статус-бар заберёт цвет, на старых iOS работает хук. Цвет статус-бара меняется без анимации, поэтому в PWA анимацию затемнения отключаем: `backdropAnimation={false}`.
- **Safe area** — через `env()`, заложено в компонент.
- **Автофокус** в поле на вебе не передаём: есть риск сломать UI.

## Дополнительно
- **Немодальная** (`modal={false}`): без затемнения, тень `shadow-medium`, экран под шторкой доступен, например карта. Не используйте её, чтобы класть контролы поверх основного экрана. Старые немодальные шторки на системную шторку iOS не меняем: для таких кейсов планируют доработать `FloatingContainer`; нашли такую — заводим баг с лейблом `cx_debt` на продуктовую команду.
- **Закреплённые элементы:** `pinnedTop` (поиск, чипы под шапкой) и `pinnedBottom`; футер закреплён всегда.
- **Скролл:** индикатор и фон под ним остаются на месте, у края — оверскролл.

## Доступность
- При открытии фокус на шторке, первый элемент в порядке фокуса — индикатор, дальше вложенные компоненты по своим правилам.
- Увеличенные шрифты — вложенные компоненты скейлятся сами.

## API
```js
h(TaigaUI.BottomSheet, {
  open, onClose: function (reason) {}, onBeforeClose: function (reason) { return true; },
  title, description, header: {/* пропсы Header */}, appBar: {/* пропсы NavigationBar */},
  children, inset, pinnedTop, pinnedBottom,
  actions: [{ label: 'Отмена' }, { label: 'Готово' }],   // последнее — основное, показывается сверху
  footer,
  height: 'auto' | 'large' | 320 | '50%', snapPoints: [300, 'large'], defaultSnap, onSnapChange,
  modal, swipeable, dismissible, closeOnEsc, grabber, barOverlay, topInset, backdropAnimation,
  hero: { image: 'trial.png', height: 300, background: 'brand-element-t-business-pale', close: true },
  system: 'ios' | 'android', topOffset, maxWidth, inline, container, label
})
```
`Dialog` с `platform="mobile"` по умолчанию открывается в этой шторке (диалог-шторка из гайда tui-dialog). `Dropdown` с `platform="mobile"` — тоже (меню и селекты).

## Пробелы
- Нативная шторка iOS (зазоры 16 / 8, скейл контента) — системная, в веб-компоненте её нет.
- Отступ футера (16 сверху, 8 между кнопками) взят из старого футера гайда: в новой версии он не размечен.
- Пресет `small` в Figma есть только у нативных вариантов.
- Тень немодальной шторки в ночных темах — `shadow-medium` там `none`.
