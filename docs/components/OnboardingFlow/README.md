# OnboardingFlow (`tui-onboarding-flow`)

Последовательная подача информации на нескольких страницах: онбординг раздела, подготовка к сценарию, объяснение новой функции. Источник — гайд `tui-onboarding-flow` (v1.3.0, 27.08.2026: iOS-компоненты под Liquid Glass). Готов на всех платформах: iOS, Android, PWA/WebView, десктоп.

Подсказка прямо на странице, у элемента, — `PopoverCard` (раздел «Обучение пользователя»).

## Мобилка
**Построение** сверху вниз:
- **Навигационная панель** (`tui-app-bar`).
  - На первом шаге «Закрыть» слева; перед закрытием можно спросить «Точно закрыть?».
  - На следующих шагах слева «Назад», «Закрыть» уходит вправо или убирается.
  - Посередине прогресс-бар. **При меньше 4 шагов его не показываем**; в Figma и в коде выключается вручную (`progress`).
- **Блок картинки** — 50 % высоты рабочей области (не всего экрана). Отдельно покрасить фон блока нельзя.
  - Картинки готовим отдельно для светлой и тёмной темы.
  - Видео стартует сначала при каждом открытии страницы.
- **Фейд** 64 поверх картинки, можно отключить (`fade: false`).
  - Нижний — в `neutral-1-opaque`.
  - Верхний (под аппбаром, у phone-bottom) — в `elevation-1`.
- **Текст** — `tui-header [large]`: заголовок и описание. Описание — Body L (iOS `ios-body-l`, Android `android-body-l`) цветом `text-primary` (решение команды, 27.10.2026). Отступы 16 по бокам и 24 сверху и снизу.
- **Кнопки** — `tui-floating-container`, его вид и поведение наследуются. Длинный текст уходит под кнопки.

**Шаблоны картинки** (`template`). В Figma это разные пресеты, в коде один блок с режимом масштабирования:
| шаблон | что |
|---|---|
| `centered` | иллюстрация 220×220 по центру, сверху 24 для оптической компенсации; размер не зависит от экрана |
| `cover` | картинка или видео на весь блок, без верхнего отступа; позиционирование можно менять |
| `padding` | как `cover`, но сверху отступ на высоту аппбара |
| `phone-top` / `phone-bottom` | скриншот в рамке телефона шириной 220: верхняя или нижняя часть. Рамка одна для iOS и Android, статус-бар накладывается поверх |
| `custom` | без картинки (только мобилка): заголовок сразу под аппбаром, ниже свой контент — ячейки, компоненты TUI или локальные |

**Большие картинки** заполняют блок, обрезаясь по ширине (iOS Aspect Fill, Android CENTER_CROP, web `object-fit: cover`).

## Десктоп
Модальное окно на бэкдропе `service/backdrop` с размытием 32. Окно: фон `elevation-1`, тень `shadow-popup`, радиус 24. Кнопки «Назад» и «Закрыть» — круглые 32 в углах (16 от краёв). На первом шаге «Назад» нет.

**Лейауты** (`layout`):
- **Вертикальный.** Ширина 600, картинка 280 сверху. Когда использовать:
  - в онбординге 1 шаг;
  - на каждом шаге не больше 4 элементов (картинка, заголовок, текст, кнопка).

  Заголовок и описание — по центру. Кнопки друг под другом по центру, ширина по тексту (решение команды, 27.10.2026). Если контента много, окно растёт под содержимое без скролла.
- **Горизонтальный** — во всех остальных случаях. Окно 800×400 с фиксированной высотой, картинка 360×400 слева.
  - Справа контент с отступами 80 / 40 / 40 / 40.
  - Сверху счётчик «1 из N» (`Body S Bold`, `text-secondary`).
  - Кнопки прижаты вправо.
  - Длинный контент скроллится, по краям фейды 8: нижний виден сразу, верхний появляется при скролле.

**Контент**: `tui-header` h4 (28/32) и описание `Body M` цветом `text-primary` (решение команды, 27.10.2026). Строки заголовка и описания выравниваются по длине (`text-wrap: balance`), чтобы на последней не оставалось одно слово. Между контентом и футером 28. Кастомный контент опционален.

**Футер**: одна или две кнопки, между ними 12. Можно сочетать кнопки с лигалом (до 3 строк, внутри бывают ссылки):
- в вертикальном лейауте лигал под кнопками, по центру;
- в горизонтальном — слева от кнопок, выровнен по левому краю.

**Шаблоны**:
| шаблон | что |
|---|---|
| `centered` | 220×220 в контейнере 280 (вертикальный) или 400 (горизонтальный) |
| `cover` | картинка или видео на весь блок: 600×280 или 360×400, экспорт @2x |
| `screen-top` / `screen-bottom` | скриншот 16:9 в рамке экрана 480×270 (сам скриншот 1280×720, PNG); только вертикальный лейаут |

Кнопки навигации поверх картинки можно перевести в стекло (`navAppearance` у шага): `glass-on-dark` — на тёмной, `glass-on-light` — на светлой цветной (как у `ButtonClose`).

**Фон блока картинки** (`mediaBackground` у флоу или шага) — имя токена без `--tui-` или CSS-цвет. Например, картинка на светлом фоне продукта.

**Появление и закрытие** — как у `Dialog`: окно со сдвигом 32 снизу и прозрачностью 0 → 1, подложка — прозрачностью; `duration-moderate`, `productive-standard`. Закрытие — так же в обратную сторону: передайте `open: false`, окно уйдёт и пропадёт через 300 мс.

## Поведение
- **Переход между шагами.**
  - Мобилка: листается только контент, аппбар и кнопки стоят на месте. `duration-moderate` (300 ms), `productive-entrance`; на iOS — системный push. Назад — свайпом вправо.
  - Десктоп: контент и картинка сменяются с fade (`productive-standard`, `duration-moderate`).
  - Позиция окна: на первом шаге окно по центру, отступы сверху и снизу равные, но не меньше 64. Дальше верхний край остаётся на месте, окно растёт вниз.
- **Загрузка картинки или видео**: пока грузится, показываем лоадер. На десктопе спиннер появляется через 1000 ms и держится минимум 800 ms. Готовая картинка проявляется за `duration-fast`, `productive-standard`.
- **Свайп вниз** (в шторке) — выбор дизайнера:
  - закрывается сразу;
  - не даёт закрыться;
  - перед закрытием Action Sheet «Точно закрыть?».
- **Скролл**: на маленьких экранах и с крупным шрифтом текст уходит под кнопки. Доскроллив до конца, видим отступ от текста до кнопок.

## PWA / WebView
- В вебе это лейаут, который встраивается в контейнер:
  - в `tui-bottomsheet` (шторка разворачивается на весь экран), в Figma — `system = PWA`;
  - в полноэкранный `tui-dialog`, в Figma — `system = WebView`. Желательно только в WebView: шторки там отображаются плохо.
- На Android подстраиваются шрифты и вид `tui-app-bar`.

## Подготовка картинок
- **Формат:** PNG (прозрачный фон — удаляем подложку), экспорт @1x, @2x, @3x. Экспортируем отдельно, не из компонента.
- **Без прогресс-бара:** холст 700×400 с запасом по бокам, основной контент — в безопасной зоне 350×350.
- **С прогресс-баром:** холст 850×400, безопасная зона 375×375 прибита к низу; размер по умолчанию 220×200.
- **Видео:** MP4 @2x; 6–7 секунд весят 130–150 КБ (оптимизировать через ffmpeg).
- **Phone frame:** в макетах растровые скрины 375×812 (iOS) и 360×800 (Android). Разработке отдаём 750×1624 и 720×1600.

## Тексты
- Объясняем, зачем это и в чем польза; интерфейс не описываем. Без «теперь», «сейчас», «стало».
- Кнопка на промежуточных шагах — «Дальше», на последнем — «Понятно».
- Общие правила текстов и коды — раздел «Тексты интерфейса» (`copy.md`): ON1–ON4.

## Доступность
- Фокус идёт сверху вниз, слева направо: аппбар («Назад»; прогресс — «Экран 1 из 3»), заголовок, описание, кнопки.
- При увеличенном шрифте контент скроллится внутри, аппбар и кнопки закреплены.

## API в коде
```js
h(TaigaUI.OnboardingFlow, {
  platform: 'mobile',            // или 'desktop'
  steps: [
    { illustration: 'face-id', title: 'Входите по Face ID', description: 'Не придется вводить код', secondaryAction: { label: 'В другой раз' } },
    { template: 'custom', title: 'Какие валюты нужны?', content: cells },
    { image: 'promo.mp4', template: 'cover', title: 'Карта уже работает' }
  ],
  onClose: close, onFinish: done
})
```
- Основная кнопка по умолчанию — «Дальше», на последнем шаге — «Понятно». Нажатие переводит на следующий шаг, если `onClick` не вернул `false`.
- Мобильный вариант заполняет родителя по высоте.
- Десктопный — оверлей поверх родителя с `position: relative` (`backdrop: false` — только окно).
- Нужен `components/illustrations.js`.

Пропсы:
- `platform`, `system` (ios · android), `layout` (vertical · horizontal; по умолчанию выбирается по правилу выше);
- шаги и навигация: `steps`, `step` / `defaultStep` / `onStepChange`, `onClose`, `closeOnSteps`, `onFinish`;
- вид: `progress` (по умолчанию от 4 шагов), `fade`, `nextLabel`, `doneLabel`;
- десктоп: `open` (закрытие с анимацией), `mediaBackground`;
- мобилка: `statusBar` — аппбар `NavigationBar` со статус-баром вместо своего: для макетов и экранов вне WebView, на iOS — стеклянные кнопки iOS 26.

Шаг: `illustration` или `image` / `screenshot`, `template`, `title`, `description`, `content`, `primaryAction`, `secondaryAction`, `legal`, `fade`, `navAppearance` (`glass-on-dark` · `glass-on-light`), `mediaBackground` (десктоп).

## Расхождения в гайде
- **Кнопки на десктопе.** На схеме «Размеры» подписаны `tui-button (Size M)`, а в самих компонентах стоят кнопки L (56). В коде — L, как в компонентах.
- **Цвет нижнего фейда** — `neutral-1-opaque`, а фон под текстом — `elevation-1`. На стыке видна полоса (в Figma тоже), на десктопе я свёл фейд в `elevation-1`. Стоит уточнить у авторов компонента.
