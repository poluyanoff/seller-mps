# FloatingContainer (`tui-floating-container`)

Кнопки, прикреплённые к низу экрана. При скролле контейнер остаётся внизу: виден всегда или появляется по триггеру или якорю. Источник — гайд `tui-floating-container` (v1.2.3). Готов на всех платформах, отступы на iOS и Android одинаковые. В Figma на нём построены футеры `tui-illustration-screen` и `tui-onboarding-flow` (в коде у этих компонентов свой футер с теми же размерами).

## Варианты (`content`)
| вариант | что | отступы |
|---|---|---|
| Action | одна primary-кнопка | бока 16, снизу 24 |
| Two actions | primary + secondary | между кнопками 8, снизу 16 |
| Action + legal | primary + текст | между кнопкой и текстом 16, блок текста min 48; текст `UI S`, `text-secondary`, по центру; ссылка в лигале — тем же серым с подчёркиванием, не синяя |
| Custom content | любой контент снизу (сумма + кнопка и т. п.) | как у одной кнопки |

Под контейнером — системная полоса (home indicator) или safe area.

## Подложка
- Градиент, чтобы контент не просвечивал под кнопками: от прозрачного у верхнего края кнопки до цвета фона за 40, дальше сплошной фон.
- Цвет подложки подстраиваем под фон экрана: `base` или `elevation-1` (`background`).
- **Показываем подложку:**
  - если кнопки две или есть кнопка и лигал;
  - если кнопка одна и видна сразу при входе на экран.
- **Не показываем:**
  - если кнопка одна и появляется при скролле;
  - если кнопка одна и появляется по триггеру (например, по нажатию на ячейку).
- В коде по умолчанию подложка есть у двух кнопок и у варианта с лигалом. Для одной кнопки включаем `fade` по правилу выше.

## Поведение
- **Появление и скрытие** (`visible`): блок поднимается снизу и опускается обратно. Появление — `expressive-entrance`, `duration-slow` (500 ms); скрытие — `productive-exit`, 200 ms.
- **Смена кнопки**: через фейд, `productive-exit`, `duration-fastest` (75 ms).
- **Смена разных элементов** (кнопка ↔ кнопка с текстом): текущий уезжает вниз, снизу приезжает новый.
- **Вторая кнопка и текст**: меняются через фейд, `productive-standard`, 200 / 300 ms.
- **Второстепенные элементы** появляются снизу. Если в начале подложки не было, а в конце она есть, подложка появляется с теми же параметрами.
- **Отступ в конце скролла — 20**: между концом контента и действиями (в коде `margin-top` у контейнера).

## Кастомизация
- **Стиль кнопок** — любой из библиотеки. Полупрозрачные кнопки сверху не ставим: из-за градиента сквозь них просвечивает контент. Для второстепенного действия — `flat`.
- **Кастомный контент** — любые локальные или библиотечные компоненты. В коде у кастомного контента подложка начинается на 24 выше и уходит в цвет фона за 24, чтобы текст не накладывался на контент.
- **Иконка в лигале** «из коробки» в коде недоступна, но легко делается руками; вопросы — в `~tui-mobile-ask`.

## Лигалы
- Серый текст для дисклеймеров.
- Только с одной кнопкой: не сочетается с двумя кнопками и не бывает без кнопки.
- Не больше 3 строк (в коде обрезается).
- Либо всегда виден при скролле, либо уносим его в контент экрана.
- Ссылки внутри — `text-action`.

## Доступность
- **Крупный шрифт**: кнопки увеличиваются по правилам `tui-button`. Лигал растёт на iOS до xLarge, на Android до 120 %, и тогда допустимо 4 строки. В мобильном вебе и PWA 4 строки — только при AX1 / 150 %. В WebView крупный шрифт пока не прокинут.
- **Озвучка**: у кнопки — лейбл и роль; две кнопки читаются по очереди. Текст фокусируется и читается целиком, ссылки уходят в дополнительные действия скринридера.
- **Важное — до кнопки**: условия вроде комиссии ставим в контент перед кнопкой. Иначе незрячий пользователь подтвердит действие, не дойдя до них.

## API в коде
```js
h(TaigaUI.FloatingContainer, { primaryAction: { label: 'Готово', onClick: done }, secondaryAction: { label: 'Условия программы', onClick: open } })
h(TaigaUI.FloatingContainer, { primaryAction: { label: 'Оформить карту' }, legal: 'Нажимая «Оформить», вы соглашаетесь с условиями' })
h(TaigaUI.FloatingContainer, { primaryAction: { label: 'Выбрать' }, visible: scrolled })   // одна кнопка по скроллу — без подложки
h(TaigaUI.FloatingContainer, { fade: true }, customContent)
```
Кладём последним элементом в скроллящийся контейнер экрана: по умолчанию `position: sticky; bottom: 0`, место под себя он оставляет сам. В мобильном `PageLayout` — последним ребёнком (без обёртки): при коротком контенте кнопки прижимаются к низу экрана, при длинном — прилипают при скролле. Шаги заявки — на `Dialog` с `fullscreen`, там футер прибит к низу сам.

Пропсы:
- кнопки и текст: `primaryAction` и `secondaryAction` (`{label, onClick, appearance, loading, disabled, secondLabel}` или свой элемент), `legal`, `children` (кастомный контент);
- подложка: `fade`, `background` (base · elevation-1);
- показ: `visible`, `position` (sticky · absolute · static), `homeIndicator` (false — без safe area);
- `system` (ios · android).
