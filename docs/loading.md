# Загрузки

Пересказ Figma-гайда «Гайд по загрузкам» (v1.0.0). Он задаёт единые правила загрузки для мобилки и десктопа:
- как и когда показывать индикаторы;
- какие тайминги соблюдать;
- как сглаживать переходы.

В примерах гайда в основном мобилка, но правила универсальны.

Гайд описывает **целевые решения для новых фич**. То, что что-то уже есть на проде, — не аргумент переиспользовать.

Компоненты: `Loader` (спиннер), `ProgressBar` / `ProgressCircle` (известная доля), скелетоны компонентов (`skeleton`), `BlockStatus` (ошибка в блоке), `Toast` («Загружается дольше обычного»). В коде правило 300/500 даёт хук `TaigaUI.useLoading`, мерцающий текст — класс `tui-shimmer-text`.

## Основные принципы
- **Показываем загрузку только при необходимости:**
  - используем кэш и предзагрузку;
  - не показываем индикатор, если операция выполнилась быстро.
- **Сглаживаем переходы.** Индикатор не должен резко появляться и исчезать:
  - задержка перед показом;
  - минимальное время показа;
  - анимации входа и выхода;
  - без частой смены состояний.
- **Не дублируем индикаторы.** За раз — один индикатор. Нельзя показывать несколько разных одновременно или переключать их по очереди.
- **Сохраняем контекст:**
  - навигация и статичные элементы (заголовки) остаются видимыми;
  - данные в блоках обновляем без перерисовки всего экрана;
  - без резких скачков лейаута.
- **Даём обратную связь.** Любая загрузка заканчивается контентом или понятной ошибкой.

## Индикаторы
### Как выбрать
| Ситуация | Индикатор |
|---|---|
| Экран загружается впервые или обновляется целиком | скелетон |
| Запущено действие, и оно выполняется не мгновенно | спиннер |
| Обновляется часть контента на уже загруженном экране | мерцающий текст |

### Скелетон
Его ещё называют «шиммер». Показывает загрузку или обновление контента на экране.
- Если скелетонов на экране несколько, они анимируются синхронно.
- **Анимация одна на все компоненты:** пульсация прозрачности 1 → 0.6 → 1, по 2 × `duration-slow` (1 с) в каждую сторону, `productive-standard`. В коде синхронность обеспечивает бандл: каждая новая пульсация стартует от общего нуля. При `prefers-reduced-motion` скелетон статичный.
- Элементы навигации скелетоном не закрываем.
- Скелетоны неинтерактивны.
- Скелетон сменяется только контентом или ошибкой, но не другим скелетоном.
- Смена на контент — кроссфейд: `duration-moderate`, `productive-standard`.

### Спиннер (`Loader`)
- **Внутри контрола** — для действия, которое запустил пользователь:
  - появляется в момент запуска и блокирует только этот контрол, остальной интерфейс не трогает;
  - размер контрола сохраняется, лоадер стоит по центру;
  - после завершения скрывается сразу, без анимации.

  В кнопке — `Button loading`.
- **Блокирующий** — для перехода в другой контекст, например по диплинку, или когда спиннер нельзя поставить в контрол:
  - появляется при активации ссылки и блокирует экран;
  - собирается на `tui-notification-middle`, скрывается по правилам этого компонента.

### Мерцающий текст
Контент уже показан, а часть его обновляется в фоне (например, «Моментальный вход»).
- Применяется к конкретным элементам: тексту, значениям.
- Данные не скрывает, взаимодействие не блокирует. Только для фоновых обновлений.
- **Анимация** — зацикленная прозрачность, цикл 1000 мс:
  - 50 % → 25 %, `duration-slow`, `productive-standard`;
  - 25 % → 50 %, `duration-slow`, `productive-standard`.
- **Смена на контент** — три последовательных этапа (`duration-slow`, `productive-standard`):
  1. старый контент скрывается;
  2. меняется размер контейнеров;
  3. появляется новый контент.

В коде — класс `tui-shimmer-text` на элементе со значением.

## Тайминги
Раздел касается только загрузки контента. Ожидание долгих процессов гайд опишет позже.

**Правило 300/500** — чтобы интерфейс не мерцал:
- **300 мс — задержка перед показом.** Если ответ пришёл раньше, индикатор не показываем.
- **500 мс — минимальное время показа.** Появившийся индикатор не скрываем раньше, даже если ответ уже пришёл.

**Время ожидания:**
| Длительность | Поведение |
|---|---|
| 0–300 мс | индикатор не показываем |
| до 3–5 с | нормальное ожидание, показываем индикатор |
| после 5 с | индикатор + тост «Загружается дольше обычного» |
| после 8–10 с без ответа | ошибка |

**Тайм-аут** нужен, чтобы не казалось, что интерфейс завис. Его величина зависит от сценария: узнайте у разработки, сколько обычно длится загрузка, и добавьте небольшой запас.

```js
// 300/500: show — показывать ли индикатор
var show = TaigaUI.useLoading(isFetching);                       // { delay: 300, minDuration: 500 }
var show2 = TaigaUI.useLoading(isFetching, { delay: 0, minDuration: 500 });
```

## Первичная загрузка (холодный старт)
- **Скелетон обязателен.** Спиннер на весь экран не используем: он не показывает структуру экрана.
- **Порядок выхода блоков из скелетона:**
  - **идеально** — весь экран выходит синхронно. Необязательные блоки (рекламный баннер) могут встроиться позже;
  - **хорошо** — синхронно выходит хотя бы первый вьюпорт, остальное догружается со скелетонами;
  - **сомнительно** — блоки первого вьюпорта появляются асинхронно. Допустимо, только если иначе нельзя (например, сторис на главной).

  Реализация на вебе и в нативе разная — сценарий согласуйте с разработкой.
- **Часть данных не загрузилась:**
  - **полноэкранная ошибка** — если без этих данных экран не работает (на экране счёта не пришли балансы);
  - **ошибка в блоке** — экран работает, а блок нет (не загрузились отзывы);
  - **ничего** — блок необязательный, и пользователю не нужно знать об ошибке (рекламный баннер).

  Как оформлять — в разделе «Ошибки».
- **Картинки** грузятся асинхронно:
  - до загрузки на их месте плейсхолдер цвета фона в форме родителя;
  - появление — фейд 150 мс, `productive-standard`;
  - не загрузилась — место остаётся пустым, без фолбэков.
- **Что показать сразу:** то, что имеет смысл без данных — навигацию («Назад», «Закрыть») и статичный заголовок, чтобы из затянувшейся загрузки можно было уйти. Кнопки действий, фильтры и всё, что зависит от данных, — в скелетонах.
- **Скролл:** весь экран в скелетоне — не скроллим, это дезориентирует. Первый вьюпорт загружен, а ниже скелетоны — скролл можно.
- **Нажатия:** уже показанный блок работает, пока ниже что-то догружается. Например, товар можно добавить в корзину, пока грузятся отзывы.
- **Повтор после ошибки:**
  - в блоке — кнопка повтора, повторяется только этот запрос, индикация — спиннер в кнопке;
  - полноэкранная — «Повторить» возвращает к скелетону всего экрана, грузим как при первом открытии.

  Не забывайте про 300/500. Если кнопку повтора нельзя показать по техническим причинам, уточните у разработки.
- **Возврат на экран** — скелетон снова не показываем. Есть кэш — сразу показываем контент, свежие данные подтягиваем в фоне и подменяем на лету. Кэш может быть и при первом заходе: балансы уже загружены на главной.
- **Натив и WebView** — принципы одинаковые. При первом открытии WebView показываем нативный скелетон, пока веб-контент не загрузится полностью, чтобы не было двух скелетонов подряд. Дальше внутри WebView — те же правила. Подробнее — в разделе «Мобильный веб: WebView».

## Фильтрация
- **На бэке** (новый запрос):
  - скелетоном закрываем элементы списка, фильтры остаются видимыми;
  - для скелетона — правило 300/500.
- **На фронте** (по загруженным данным) — без скелетонов, с последовательными микроанимациями, чтобы изменения были заметны:
  - скрытие — opacity 100 → 0, `duration-fast`, `productive-standard`;
  - появление — opacity 0 → 100, `duration-fast`, `productive-standard`.
- **Счётчик на кнопке подтверждения** («Показать 15 моделей») обновляем без анимации. Если обновление дольше 300 мс — спиннер в кнопке. Подробнее — в разделе «Фильтры и сортировка».

## Отрисовка скелетонов
**Принципы:**
- **Форма родителя.** У кнопок, аватаров и бейджей — размер и радиус контейнера. Для текста — готовый текстовый скелетон.
- **Размер** совпадает с контентом, если он известен заранее. Если нет — усреднённый, чтобы при подмене не было скачков.
- **Не вкладываем скелетон в скелетон.** Закрываем либо внешний контейнер целиком, либо части по отдельности.
- **Сложные компоненты упрощаем** — скелетоним только основу.

**Текст:**
- В Figma — `tui-skeleton [text]` под каждый текстовый стиль. В коде высота считается по алгоритму из спеки компонента.
- Ширину выбирает дизайнер. Однострочный текст — усреднённое значение. Многострочный — случайная ширина строк в пределах 60–100 % блока.

**Компоненты:**
- Кнопки, аватары, чипы, бейджи — скелетон закрывает компонент целиком (`skeleton` у компонента).
- Составные (`Header`, `Cell`) — части закрываем по правилам текста и вложенных компонентов. Если элементов много, скелетон упрощаем.
- Карточки `CardLarge` и `CardMedium` — скелетоном закрывается только внешний контейнер, части не закрываем.

**Списки и стеки:**
- Количество скелетонов — в идеале столько же, сколько загрузится элементов. Если заранее неизвестно — статистически: чаще всего приходит 2 элемента → 2 скелетона.
- Однострочный стек — одинаковые скелетоны со средней шириной контента.
- Многострочный список — чередуем разную ширину.

**Формы** — кнопку сабмита в скелетоне можно не показывать. Поля и переключатели — по правилам компонентов.

**Цвет скелетона** может быть разным в пределах экрана, но всегда контрастен фону. Если фон известен заранее (цвет шапки продукта), показываем его. Если нет — скелетон на базовом фоне.

**Платформы:**
- **Десктоп и PWA** — скелетон наследует размер и радиус контейнера. Можно генерировать полуавтоматически или рисовать вручную.
- **iOS и Android** — экран со скелетонами верстается отдельной вьюшкой.
- **Figma** — у компонентов кита есть встроенные шаблоны скелетонов.

## Ленты и списки
**Стратегия подгрузки:**
- **идеально** — бесконечный скролл с ленивой подгрузкой: контент приходит в фоне быстрее, чем пользователь доходит до конца, и индикаторов он не видит;
- **допустимо** — пагинация: индикатор появляется каждый раз в конце загруженной страницы.

Стратегию обсудите с разработкой — у ленивой подгрузки могут быть технические ограничения.

Это правило для мобильных лент и списков. На десктопе в листингах основной способ — «Показать еще», постраничная — при массовых действиях (раздел «Пагинация»). В мобилке «Показать еще» — опция, если автоподгрузка не подходит (предварительное решение команды, 25.10.2026).

**Индикатор подгрузки:**
- лента из карточек — один ряд скелетонов;
- список или лента из ячеек — три скелетона;
- после загрузки позиция скролла сохраняется.

**Ошибка в ленте:**
- `BlockStatus` без фона прямо в ленте. Вертикальные отступы одинаковые для всех лейаутов, текст можно менять.
- Плавающие контролы не должны перекрывать ошибку.
- Есть кнопка «Повторить». После нажатия в ней спиннер, блок ошибки виден до ответа.
- Скелетон → ошибка и ошибка → контент — анимация `duration-moderate`, `productive-standard`.

## Будет в следующих версиях гайда
- первичная загрузка: холодный старт, моментальный вход, офлайн;
- поиск: с саджестами и без, загрузка результатов;
- переход в другой контекст: WebView, диплинки, внешние сервисы;
- pull-to-refresh;
- долгие процессы;
- подгрузка графики: картинки и иконки в карточках, аватарах, стеках;
- доступность: озвучка загрузки.

Кейсы и идеи для гайда — в канал ~tui-design-ask.

## Пробелы в ДС
- **`tui-notification-middle`** (блокирующий спиннер) в ДС нет.
- **Текстовый скелетон** `tui-skeleton [text]` в ДС нет. Алгоритм расчёта высоты описан в его спеке, а её в материалах нет. Пока скелетоним через `skeleton` у компонентов или блоки с фоном `tui-service-skeleton`.

## Связь с другими разделами
- **Поля и селекты** («Формы», `Select`) переведены на 300/500: раньше лоадер держался минимум 800 мс.
- **Вебвью — исключение.** Первоначальная загрузка WebView на стороне компонента: общий лоадер по центру экрана допустим как запасной вариант, кроссфейд скелетона в контент — `duration-slow`. Внутри веб-страницы — правила этого раздела. Подробнее — в «Мобильный веб: WebView».
