# Личный кабинет: веб и PWA

Это пересказ Figma-гайда «Онбординг в ЛК» (страница «Для дизайнеров ЛК», v1.0.0): как рисовать новый интернет-банк — десктоп и мобильный веб / PWA. Правила загрузки, навигации и сейфзон внутри приложения описаны в разделе «Мобильный веб: WebView». Здесь — то, что относится именно к ЛК.

## Кратко
- Мобильные компоненты берём из **TUI Mobile**. Сначала проверяем в сторибуке (раздел `@tui-react`), разработан ли компонент. Если нет — берём десктопный.
- Десктопные компоненты — из **TUI Desktop**.
- Общие блоки ЛК — из библиотеки **IB Blocks**.
- Максимально используем TUI. Чего-то не хватает — пишем в `~tui-design-ask`.
- **Фон белый (`tui-background-base`), карточки с тенями**, где это уместно.
- В макетах держим порядок: секции и хелперы. Общие блоки описываем по инструкции.
- Перед разработкой отправляем макеты в `~design-cross-review`.
- Не используем: **[Legacy] TUI Desktop 2022** и **[Legacy] IB.Library**.

## Концепция
ЛК переделывается как **PWA** — веб-приложение, которое работает в браузере и ставится на рабочий стол смартфона, с пушами и камерой. Десктопная версия тоже есть. Цель:
- мобильный веб по UI приближен к нативу;
- паттерны консистентны с нативными приложениями;
- десктоп консистентен с мобилкой.

Архитектура: интернет-банк (tbank.ru/mybank) написан на React с микрофронтами. Страница делится на блоки, за каждый отвечает своя команда. Инвестиции и Путешествия живут на своих React-платформах, но UI всё равно собирается на ДС. Т-Бизнес и часть внутренних продуктов сделаны на Angular.

## Процесс
1. **Макет.** Не рисуем без задачи. Оформляем по инструкции на основе ДС.
2. **Кросс-ревью** в `~design-cross-review`: проверяют консистентность, адекватность и соответствие ДС.
3. **Описание блоков.** Если блок может пригодиться другим фичам, описываем его подробно (гайд по сборке блоков).
4. **Разработка.** Прикрепляем ссылку к задаче и пингуем менеджера. Дальше спецификация и разработка, затем дизайн-ревью.
5. **Дизайн-ревью.** Проходит после тестирования или параллельно с ним, можно ревьюить и отдельные блоки (через сторибук).
   - На смартфоне: VPN, тестовый аккаунт, тестовый сайт в браузере. Дополнительно — в установленном PWA.
   - На компьютере: тестовый сайт. Мобилку смотрим в DevTools: ⌥⌘I, затем ⌘⇧M и обновить страницу.

Чаты: `~PWA-IB: design` — вопросы по дизайну ИБ, `~tui-design-ask` — по ДС, `~tui-react-ask` — технические.

## Десктоп и мобильный веб отличаются
У компонентов для PWA мобильные версии по UI идентичны нативу. Десктопные отличаются:
- **палитра:** на десктопе цвета контрастнее (secondary контрастнее, ссылки и фон тоже), потому что у мониторов хуже контраст. На мобилке secondary светлее, ссылки и фон мягче;
- **шрифты:** на десктопе T-Sans для заголовков и Neue Haas Unica для текста. На мобилке — системные: SF Pro на iOS, Roboto на Android;
- **стили компонентов:** на десктопе местами другие скругления.

## Старые макеты — не копировать
В Figma много старых макетов ЛК: серый фон, карточки с маленькими паддингами и без теней. Это устаревший дизайн. Новые макеты собираем на новых TUI-компонентах: белый общий фон, карточки с тенями или на сером фоне.

Если пересобрать нельзя, поможет плагин **lk-redesign**:
1. Обновите библиотеку.
2. Выделите плагином все инстансы.
3. Переключите mode переменных `tui-card-large` с `compact` на `normal`.

Им же можно массово сменить фон фреймов и добавить тени. На больших страницах он работает медленно — разнесите макеты по страницам.

## Мобильный веб
- Лейауты как в нативе. Ширина 375, учитываем корнер-кейсы.
- Блоки могут только сужаться: иконки и текст внутри пропорционально не уменьшаются.
- Компоненты из TUI Mobile. Наследуем UX/UI натива, но не копируем вслепую.
- **Вьюпорт** ограничен статусбаром и home indicator. Внутри — контейнер с отступами: 16 по бокам, 20 между блоками. Контент упирается в home indicator или таббар с отступом 20.
- **В браузере** вьюпорт дополнительно режет панель браузера. Установленный PWA выглядит как обычное приложение.
- **Эффекты нажатия — как в iOS.** Рипплов на Android нет.
- **Платформозависимые компоненты** (например, аппбар) рисуем в версии iOS, на Android код заменит их сам.
- **Шрифты** менять не обязательно, в коде они станут мобильными. Если оставили десктопные — предупредите разработчиков.
- **Десктопный компонент в мобиле** ведёт себя по-десктопному: дропдаун не станет шторкой, нажатия могут быть не адаптированы.
- **Переходы между страницами мгновенные**, без фейда, пуша и слайда. С анимацией открываются только шторки.
- **Модальных стеков нет.** Новый экран — новая страница с кнопкой «Назад». Заголовок отдельный или в аппбаре. Шторки можно, но не вкладывать друг в друга.
- **Статусбар в PWA** не наследует цвет фона экрана, его задают отдельно. При шторках скажите разработчикам — в ките есть окраска статусбара в модалках.
- **Тосты** вылетают от края вьюпорта. С ними лучше не использовать нативный навбар.
- **Отступы.** У разработчиков паддинги общие на контейнер, у нас встроены в каждый блок. Кастомить не надо.
- **Формы.** Структура на мобилке и десктопе одинаковая, различаться может только UI блоков. Если на десктопе форма — несколько карточек с полями, на мобилке она не превращается в пошаговый флоу. Инпуты — в стиле мобильного `tui-textfield`, длинный текст обрезается, а не уходит в фейд. Для выбора из списка — шаблоны смарт-полей: единичный в шторке, множественный, комбобокс.
- **Тёмная тема.** Показываем разработчикам экран в тёмной теме — только в дефолтном состоянии, весь флоу дублировать не нужно.
- **Чувствительные данные (sensitive mode)** — тоже только дефолтное состояние, по гайду `tui-sensitive`.

## Десктоп
- Компоненты — из **TUI Desktop**. Это актуальная библиотека, она поддерживается.
- **Лейаут ИБ свой, не китовый:** две колонки, большая и маленькая. Маленькая может стоять слева или справа, отступы и правила при этом сохраняются. Контент шириной **1104**, между колонками **96**, между блоками в колонке **32**. Шаблоны — в TUI Templates (см. «Шаблоны экранов» → «Интернет-банк / ЛК»).
- **Фон белый, карточки с тенями.**
- **Расширяем функциональность.** Не растягиваем мобильные блоки, а используем большой экран, чтобы дать больше пользы.
- **Модальность соответствует мобилке:** шторка на мобилке — диалог на десктопе, отдельная страница — отдельная страница. Шторка на мобилке не может стать отдельной страницей на десктопе.
- **Модалок внутри модалок нет** — из таких сценариев на десктопе трудно выйти.
- **Нотификации** показываем поверх навигации, с отступом **32** сверху.

## Эталонные макеты
В гайде есть «идеально собранные и оформленные» макеты. Их можно брать как шаблон оформления, для каждого — пара Desktop 1360 + Mobile 375:
- **Разводящая платежей:** скелетон; тяжёлый клиент со счетами на оплату; без контактов; без счетов и избранного; неавторизованный; тёмная тема. Для каждого состояния — дизайн и тексты.
- **Перевод по номеру телефона:** скелетон; вход через поисковую выдачу с подтянутыми контактами; тёмная тема; чувствительный режим.

Вывод для оформления: показывайте скелетон, ключевые состояния данных (пусто / мало / много / неавторизован), тёмную тему и sensitive в дефолтном состоянии, а рядом с дизайном — тексты.
