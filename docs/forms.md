# Формы и поля ввода

Пересказ гайда «tui-input / tui-textfield / tui-select / tui-combobox / tui-textarea»: производные поля, формы, редполитика и миграция. Устройство базового поля (размеры, состояния, подсказки, ошибки, очистка, доступность) — в карточке компонента **Input**.

## Редполитика полей
**Лейблы:**
- без двоеточий;
- с большой буквы, капс только в аббревиатурах (БИК);
- без «Введите», «Укажите» — существительное, которое называет содержимое;
- без спецсимволов, кратко.

Примеры: «Введите E-MAIL» → «E-mail», «Укажите цель визита» → «Цель визита», «№ паспорта» → «Номер паспорта».

**Ошибки:**
- по-человечески, без машинного языка;
- говорят, что сделать, конкретно;
- объясняют, зачем поле нужно.

Примеры: «Неверный формат данных» → «Введите адрес в формате some@mail.ru», «Обязательное поле» → «Нужен номер, чтобы курьер мог связаться с вами».

**Подсказки:**
- неочевидный формат без маски — подсказка в плейсхолдере;
- длинная — под полем;
- формат ввода не прячем только в плейсхолдер: пишем в описании, а лучше даём маску. Пример: «Номер счёта — 20 цифр, без пробелов и дефисов».

**Длинное значение** — многострочное поле, чтобы был виден весь текст.

## Выбор из списка: что брать
| Тип | Когда | Особенности |
|---|---|---|
| **Селект** | до 10–15 значений, один выбор (способ оплаты); на мобилке оптимально 5–7 | без поиска, своё значение ввести нельзя |
| **Комбобокс, строгий** | больше 15 значений, один выбор (категория расходов, страна) | ввод работает как поиск, невалидное значение сбрасывается при потере фокуса; фильтрацию отключить нельзя |
| **Комбобокс, гибкий** (по умолчанию) | больше 15, можно своё (профессия, адрес, новая категория) | список фильтруется, нет совпадений — список скрывается; фильтрацию можно отключить |
| **Автокомплит** | свободный ввод + подсказки (адрес, имя) | список только при вводе и только с совпадениями, без шеврона, всегда с индикатором загрузки |
| **Мультиселект** | несколько значений (интересы) | чекбоксы в списке; поиск и своё значение — опционально; на мобилке только веб |

**Десктоп:**
- Поле наследует базовое, список наследует `tui-dropdown`.
- Выбранный пункт отмечен иконкой справа.
- Максимальная высота длинного списка по умолчанию **400**, дальше скролл.
- Пункты можно группировать заголовками.
- Пресеты пунктов:
  - текст;
  - текст + описание сверху или снизу;
  - текст + аватар + описание.
- Шеврон при открытии поворачивается на 180° против часовой (`productive-entrance`, `fast`).
- **Загрузка:**
  - лоадер в поле появляется через **300 мс** и показывается минимум **500 мс** — правило 300/500 из раздела «Загрузки»;
  - список не скрывается при повторных запросах;
  - подгрузка длинных списков — лоадер внизу;
  - ошибка — «Не загрузилось. Повторить», по нажатию ячейка без анимации меняется на лоадер.
- **Селект:** без плейсхолдера лейбл в фокусе остаётся на месте. Нужен поиск — комбобокс.
- **Очистка:** по умолчанию поле очищается, фокусируется и открывает список. Альтернатива — очистить без фокуса.
- **Клавиатура:**
  - ↑ / ↓ — перемещение по списку, выделенный пункт обведён рамкой;
  - Enter или пробел — выбрать;
  - Esc — закрыть;
  - Enter или ↓ — открыть закрытый список.
- **Мультиселект:**
  - выбранное показываем текстом через запятую, счётчиком («Выбрано 2 из 10») или чипами (только десктоп, `tui-input-chip` с шевроном);
  - чекбоксы слева или справа (с аватаром).
- **В Figma:** `tui-input` с `input-type: select`. Список — `tui-dropdown` в автолейауте с полем, отступ **4**. В коде — `TaigaUI.Select`, `TaigaUI.Combobox` (`strict` — строгий), `TaigaUI.Autocomplete` (карточка Select).

**Мобилка:**
- Два вида списка:
  - **шторка** — один выбор без ввода (селект), по правилам `tui-bottomsheet`;
  - **полноэкранный** — с вводом (комбобокс, автокомплит).
- В нативе списки есть только в SmartFields v3.
- **Полноэкранный список:**
  - поле в фокусе уезжает наверх экрана, под ним появляются саджесты (`productive-entrance`, `moderate`, opacity 0 → 1);
  - закрывается выбором саджеста, кнопкой «Далее» / «Готово», тапом по пустому аппбару, свайпом вниз (iOS) или вправо (Android);
  - текст в поле и в саджестах выровнен по одной линии, аватар — по линии поля;
  - пресеты: текст + описание, текст + аватар + описание, текст + значение;
  - нажатие — как у `tui-cell`.
- **Селект:** после выбора шторка закрывается, фокус переходит к следующему полю (переход можно отключить).
- **Ошибка валидации:** сначала показываем хинт с ошибкой, список — после изменения текста.
- По умолчанию список перекрывает хинт, можно показывать оба.
- В мультиселекте чекбоксы всегда справа.
- **В Figma:** `tui-textfield` с `chevron-down` справа; шаблоны `template-field-with-list` и `template-bottomsheet-cell-list`. В коде — те же компоненты с `platform="mobile"`: селект в шторке, комбобокс и автокомплит — полноэкранный список.

## Многострочное поле (`tui-textarea` / `tui-textfield [multiline]`)
В коде — `TaigaUI.Textarea` (карточка Textarea).
- Наследует базовое поле.
- **Авторост** на 1 строку (на мобилке — единственный режим). Можно задать min-height, тогда одна строка выровнена по базовой высоте.
- **Фиксированная или максимальная высота** (десктоп):
  - переполнение уходит в скролл внутри текста, скроллбар виден сразу;
  - лейбл, иконки и счётчик на месте;
  - скролла лучше избегать.
- **Ручной ресайз** (десктоп, `show-dragger`) по одной или двум осям.
- **Счётчик:**
  - внутри поля (десктоп, компактно, справочно) или под полем (когда лимит влияет на результат);
  - по умолчанию сверх лимита вводить можно, лишнее подсвечивается красным, поле в ошибке;
  - можно запретить ввод сверх лимита.
- **Правила:**
  - лимит задаём так, чтобы большинство его не заметило;
  - справа одна иконка — крестик выключаем или подсказку выносим;
  - высоту подбираем так, чтобы последняя строка не обрезалась;
  - счётчик + драггер — счётчик выносим наружу.
- **Мобилка:** accessories выровнены по центру, место под них зарезервировано. Область нажатия по высоте — 56.

## Поле с чипами (`tui-input-chip`, только десктоп)
В коде — `TaigaUI.InputChip` (карточка InputChip).
- Чип создаётся по Enter или по заданному разделителю (пробел, запятая, точка с запятой, свой символ). Маска поддерживается.
- **Редактирование:** двойной клик по чипу, Enter — сохранить.
- **Переполнение:**
  - по умолчанию поле растёт по высоте;
  - фиксированная высота обрезает чипы — не рекомендуется.
- **Длинный чип:** максимум 32 символа, дальше многоточие, полный текст в тултипе.
- **Ошибки:** общая (поле красное, текст снизу) или на конкретном чипе (тултип на чипе).
- **Клавиатура:**
  - Enter — сохранить чип или редактировать выбранный;
  - Backspace — удалить выбранный чип или выбрать предыдущий;
  - стрелки — переход между чипами;
  - Esc — отмена.
- Лейбл — **только снаружи**.
- Может работать как мультиселект.

## Поле поиска (десктоп `tui-input-search`; мобилка — `tui-search-bar`, в коде компонент `SearchBar`)
- **Лейбл обязателен** и описывает, где ищем: «Поиск по статьям», «Имя или номер телефона». Без «введите» и без многоточий.
- **Плейсхолдер** необязателен:
  - даёт пример или указание: «Справки», «Введите как минимум 3 символа»;
  - не дублирует лейбл;
  - без «например», точек и кавычек.
- **Подсказки в списке** — по правилам `tui-dropdown`:
  - выбранное подставляется в поле;
  - нет совпадений — «Ничего не найдено»;
  - загрузка — 300 / 500 мс, как в списках.
- **Мобильный веб:** React — `tui-input` из platform-ui в стиле iOS, Angular — `<input TuiSearch>`.

## Поле с суммой
В ДС — `TaigaUI.InputAmount` (карточка InputAmount).
- **Код:** натив — `tui-textfield [number]`; React — InputAmount (мобилка) или InputNumber (десктоп); Figma — `tui-input-number`.
- На мобилке **крестик всегда выключен**.
- **Форматирование** (автоматическое, все пробелы неразрывные):
  - разряды по 3 начиная с 4 цифр: 1 000, 1 000 000;
  - дробная часть — всегда 2 цифры (299,90) или скрыта, если нули; цвет как у целой части; разделитель по локали;
  - плюс `+` (U+002B) и минус `−` (U+2212), без пробела, без дефиса и тире;
  - валюта в русском интерфейсе справа через неразрывный пробел, без знака — код латиницей (MXN); в иноязычном — слева без пробела;
  - процент без пробела.
- **Крупный шрифт:** только без лейбла, на десктопе только L, без крестика.
- **Всегда заполненное (uncleanable):** 0 при входе; ввод заменяет ноль; при пустом поле и потере фокуса снова 0.
- **Справа** можно поставить иконку или кнопку («+100», «+1 000»).
- **Саджесты** — кнопки сумм под полем («100 ₽», «500 ₽», «1 000 ₽»). Подставляют сумму, собираются вручную.
- **Озвучка:** «100 знак рубля» → читается как «100 рублей», «100 долларов».

## Поля с маской
В ДС — `TaigaUI.InputPhone`, `TaigaUI.InputPassword`, `TaigaUI.InputDate` и `TaigaUI.InputTime` (карточки InputPhone, InputPassword, InputDate, InputTime). ИНН — базовое `Input`.
- **ИНН** — отдельного пресета нет, базовое поле.
  - Плейсхолдер: «10 цифр» (юрлица), «12 цифр» (физлица и ИП), «10 или 12 цифр» (оба).
  - Ошибки: «Напишите ИНН», «ИНН — 10 или 12 цифр», «Проверьте ИНН».
- **Пароль** — десктоп `tui-input-password`, React — inputPassword, мобилка — `tui-textfield`.
  - Кнопка показать / скрыть, на десктопе с тултипом «Показать пароль» / «Скрыть пароль».
  - На формах входа вместо неё можно «Не помню», тогда крестик выключаем.
  - Типовые ошибки: «Напишите пароль», «Неправильный пароль», «Минимум N символов», «Максимум N символов», «Пароль и подтверждение не совпадают».
- **Дата** — `tui-input-date`, в коде `TaigaUI.InputDate` (карточка InputDate):
  - маска ДД.ММ.ГГГГ, остаток маски виден серым по мере ввода;
  - десктоп — календарь в выпадашке под полем (`CalendarDropdown` без футера, саджесты «Сегодня», «Завтра»); мобилка — календарь в шторке;
  - отдельной страницы в Figma-гайде полей нет: собрано по правилам `Input` и `Calendar`, пробелы — в карточке.
- **Время** (только десктоп, `tui-input-time`):
  - маски ЧЧ:ММ:СС и ЧЧ:ММ, формат 24 или 12 часов;
  - больше 24 или 59 ввести нельзя; неподходящая первая цифра заменяется на 0 (9999 → 09:09);
  - плейсхолдер виден по мере ввода; при потере фокуса нули дописываются (09 → 09:00);
  - саджесты: интервал по умолчанию час, можно ограничить диапазон или исключить отдельные интервалы.
  - в коде — `TaigaUI.InputTime` (карточка InputTime).
- **Телефон:**
  - без фокуса только лейбл «Телефон»;
  - в фокусе предзаполнен код +7, он не стирается — это часть значения, а не префикс;
  - маска РФ без скобок: +7 921 123-45-67 (этот же номер — плейсхолдер);
  - при вставке «8 900…» код отрезается → +7 900…;
  - ввод в середину сдвигает символы вправо.

## Поле со слайдером (только десктоп)
- `tui-input-slider` и `tui-input-range` (React — один InputSlider).
- **Всегда заполнено:** нет пустого состояния и крестика. В range нет end-accessories.
- **Форматирование** разрядов и знаков, префиксы и суффиксы — общие для обоих значений.
- **Значения:**
  - любой шаг;
  - метки, с привязкой или без («снэппинг», ручной ввод округляется к ближайшей);
  - нелинейная шкала для больших диапазонов;
  - свои подписи («Сегодня», «Через неделю»);
  - прошлое без минуса («15 дней назад»).
- **Клавиатура:** Tab / Shift+Tab — между инпутами (слайдер фокус не получает), стрелки — ± шаг.

## Формы
**Мобилка:**
- Форма — контейнер полей с логикой, валидацией, форматированием и навигацией. Работает на экране, в шторке и модалке.
- В нативе — SmartFields, в вебе — обычные поля: они умеют списки, валидацию и форматирование.
- **Отступы:**
  - между полями **12**, в том числе составными и при подсказках или ошибках;
  - боковые 16 заложены в `tui-textfield`.
- **Обязательные поля не помечаем.** Показали — значит обязательное. Необязательное по возможности убираем или помечаем в лейбле.
- **Переход фокуса:**
  - только между подряд идущими активными полями, disabled, read-only и tap-only пропускаются;
  - элемент между полями снимает фокус;
  - над клавиатурой кнопка «Дальше», на последнем поле — «Готово» (скрывает клавиатуру). Это `tui-button` primary-accent M, отступ до клавиатуры 16, до поля после автоподскролла 12.
- **Автоподскролл:**
  - поле вне видимой области поднимается над кнопкой «Дальше» / «Готово»;
  - в вебе подскроллом управляет браузер;
  - тап по неактивному месту снимает фокус.
- **Валидация:**
  - постоянная — для масок;
  - при расфокусе — пустые не валидируем;
  - после сабмита — кнопка всегда доступна, прокрутка к ошибкам, сильная тряска, при повторе слабая.
- **Составные поля** (только натив, SmartFields): без фокуса это одно поле («Фамилия, имя, отчество»), в фокусе — несколько.
- Шаблоны форм — в TUI Templates.

**Десктоп** — отступы зависят от размера полей:

| Отступ | L | M | S |
|---|---|---|---|
| между полями | 20 | 16 | 12 |
| от подсказки до следующего поля | 16 | 12 | 8 |
| между полями в ряд | 20 | 16 | 12 |
| от последнего поля до кнопки | 32 | 24 | 20 |

Размер полей по умолчанию — **L**, так клиентские формы получают его без `size`. M и S задают явно для служебных и плотных экранов (карточка Input).

**Ширина полей** (десктоп; решение команды, 25.10.2026):
- одиночное поле в карточке, колонке формы или шаге — на всю ширину контейнера, без пустого места справа;
- поля в ряд — сетка из колонок, их столько же, сколько полей; ряд заполнен до правого края, пустых колонок нет. Два поля — две колонки, а не три с пустой;
- по умолчанию колонки равные. Поле с заметно коротким значением («Дом», «Корпус», «Единица») можно сузить, остаток ширины забирает соседнее поле ряда;
- узкое поле не стоит в одиночку: «ширина по содержимому» из карточки Input — только для полей в ряду.
- `TaigaUI.check()` ловит это правилом `field-width`: поля L и M в своей вёрстке внутри `CardLarge`, `Dialog` или колонки `PageLayout`. Поля S, поиск с лупой, ряды с чипами, сегментами и табами и поля внутри других компонентов (фильтры, таблицы) не проверяет.

**Мобилка** — между полями в ряд **12** (дата выдачи и код подразделения, даты начала и окончания). Ряд — сетка из равных колонок, поля экрана 16 только снаружи ряда.

## Миграция макетов
- **Без префикса** — актуальный компонент.
- **`[legacy]`** — устаревший дизайн, но ещё поддерживается в коде.
- **`[deprecated]`** — только для миграции.

Старые поля можно оставить в уже сделанных макетах, но мигрировать нужно, если:
- разработка пойдёт на ките с новыми полями;
- фичу будут обновлять;
- в нативе простые поля без смарт-функций;
- нужен native-like UI в мобильном вебе.

Оставить старые можно, если продукт остаётся на Taiga 3.x или platform-ui, либо в новых полях нет нужной функции (запрос в `~smartfields-ask`).

**Автоматически** — плагин **TUI Migrator**:
1. Примите обновления библиотеки (Show updates for all pages → Update all).
2. Импортируйте плагин из manifest.json.
3. Выделите фреймы и запустите миграцию.

Потом проверьте иконки справа: Reset Instance → иконка из small-pragmatic, при необходимости включите `show-end-accessories` и `show-input-type`.

**Вручную:**
| Было | Стало |
|---|---|
| `[legacy] tui-input` | `tui-input` |
| `[legacy] tui-input-slider` | `tui-input-slider` |
| `[legacy] tui-input-tag` | `tui-input-chip` |
| `[legacy] tui-input-search` | `tui-input-search` |
| `[legacy] tui-textarea` | `tui-textarea` |
| `[deprecated] tui-textfield` | `tui-textfield` |
| `[deprecated] tui-textfield [multiline]` | `tui-textfield [multiline]` |
| `[deprecated] tui-textfield [sum]` | `tui-textfield [number]` |

После замены верхний лейбл и описание включаем руками. Из TUI Desktop 2022 ничего не переносится.
